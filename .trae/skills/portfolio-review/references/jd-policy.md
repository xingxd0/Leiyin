# 内部 JD 评审规则

严格在作者信息确认之后进入此阶段。没有 JD 可直接跳过。JD 不改变作者已确认的通用角色，不重写通用评分。

## 拆解

逐条记录：原文位置、要求摘要、所属六维、类型（核心能力/必备/加分）、明确性、要求的证据。依据职责和措辞判断，不按关键词次数机械加权。一个要求可关联多维，但只设一个主要计分归属。

- 核心能力：影响岗位评审重点和权重。
- 必备条件：单独核对，不能被高总分抵消。
- 加分项：有证据体现优势，缺少不当作硬性不合格。
- 没有写明的要求不伪装为 JD 原文，必要推断标注并核实。
- 只核对与岗位能力相关的信息，不从姓名、照片等推断年龄或其他无关个人属性。

目标层级从职责范围判断而非公司职称直接映射。层级有歧义时提供简洁摘要让操作者确认。求职者的通用参照与岗位参照不同，两个分数须分别对照标准，不能只改变权重后沿用同一组原始分数。

## 岗位权重：初稿中的明确默认

用户确认了允许 JD 调整权重，但尚未指定自动调整公式或上下限。本稿不引入自动关键词倍率或固定偏移量。

1. 以该作者主方向的通用权重为起点。
2. 阅读 JD 的核心职责与能力要求，提出明确的六维岗位权重；六项均为正数、总和为 100。
3. 每个变化记录 JD 依据、改变的评价重点和理由。若 JD 不足以支持调整，沿用通用权重，不虚构差异。
4. 评分前冻结本次岗位权重；不能看到分数后调权重以美化结果。操作者可以在内部查看或修改，对外报告不披露权重。
5. 该方法与权重数值均需通过真实样本校准，不能宣称已验证可预测录用结果。

## 要求覆盖状态

| 状态 | 使用条件 |
|---|---|
| 已有证据 | 作品提供了具体、相关且足以支持的行为或成果 |
| 部分支持 | 有相关证据，但范围、深度或验证尚不足 |
| 证据不足 | 没有展示、不可读或需要补充，不能断言不会 |
| 明确不符合 | 有直接事实与要求冲突，例如确认的经验与明确必备年限不符 |

缺少 JD 所需证据不等于真实能力不合格。岗位分是作品对岗位要求的呈现匹配，不是录用概率。未满足或未证实的必备项要在报告单独列出，无论总分高低。

报告可写 JD 明确要求和对应作品事实，不输出原文位置之外的内部评分矩阵、公式、阈值或层级细则。操作者内部保留映射记录用于复评。
