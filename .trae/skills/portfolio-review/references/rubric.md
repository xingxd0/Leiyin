# 内部评审细则 v0.1

本文件仅供操作者与评审执行使用，不附入候选人报告。六维与三类权重已确认；具体 1–5 档锚点、计算与缺项处理是可校准的初稿细化，不声称经过真实样本验证。

## 核心宗旨

判断作品是否证明设计介入的价值，以及作者相对所选能力层级、岗位要求和常规执行要求体现了什么判断与贡献。没有可比样本时不输出同行百分位、胜率或真实职业能力排名。

作品事实 → 判断 → 对读者/用户/业务的影响 → 修改建议 → 完成标准，是每个结论的基本结构。不要以泛泛夸奖或“提升体验”“加强视觉”代替具体解释。

## 六维

### 1. 业务理解与目标定义

陌生评委应能理解产品、用户、使用场景、改动原因、约束与职责。信息可以分布在不同位置，不强制单独的介绍页。

检查业务目标是否转化为设计可影响且可验证的因素。例如提升 GMV，需识别流失发生在哪个环节及设计为何优先作用于此。业务与设计目标同为转化率也可成立；目标拆得多不自动加分。

1 分：背景或目标难以识别，设计与业务关系未交代，或明显矛盾。
3 分：背景足以理解，目标有合理联系，但问题定位或衡量依据有限。
5 分：基于证据定义问题、明确设计作用与优先级、可验证且交代限制。

非商业项目用传播目标、公共服务目标、用户任务或探索目标适配，不强制套用 GMV。

### 2. 设计策略与方案推导

检查目标 → 策略 → 方案/原型的因果假设与实际对应关系。减少步骤应回应实际障碍；视觉优化应解释如何影响理解、信任或关键行为。两者都不自动正确或错误。

A/B/C 对比须针对同一问题、遵守可比的关键约束、使用一致标准，并呈现真实的可选价值。不强求复杂度、完成度相同；差异应被说明。明显弱的替代方案只能说明对比证据不足，不无证据指控“陪稿”。选择 A 或合成 D 要说明取舍、依据与新的验证需求。

1 分：策略停留在口号，方案与目标脱节，或选择依据自相矛盾。
3 分：主要策略落入方案，对比与选择基本合理，但关键假设证据有限。
5 分：目标、策略、方案一一可追溯，公平比较替代路径，解释约束与验证。

### 3. 方案深度与经验匹配

复杂度看不确定性、约束冲突、决策范围、跨角色协作、关键与异常状态、影响范围及作者负责的层次。按 B/C 与所选层级适配，不按项目名字或页面数推断复杂度。

“分析十页、方案两页”是检查信号：每段分析是否产生并改变设计判断？内容是否重复？少量改动也可能带来高价值。登录、组件、规范项目可能涉及跨市场、风控或体系治理，也可能只是基础执行。

原型与实现应服务目标和策略，覆盖必要状态、真实约束和验证。AI Coding 方向还看作者如何定义任务、审查输出、处理异常与验证可用性，不能仅凭工具名、截图或宣称“能跑”判定质量。

1 分：在所选层级下只展示表面执行，关键流程或约束缺失，分析与落地脱节。
3 分：方案完整程度与复杂度基本满足所选层级，但边界或系统性有限。
5 分：在该层级所需深度上清晰解决关键冲突与边界，有相称的方案和落地证据。

### 4. 视觉设计与表达

源于操作者提供并引用的《沉淀UI设计Skill》中的框架；本文件是针对作品集评审的整理，不代表已安装该技能。

| 子项 | 检查内容 |
|---|---|
| 形 | 形状、组件、圆角、图标、线条是否一致并适合语境 |
| 色 | 色彩关系、对比、语义、品牌与可读性 |
| 字 | 字号、字重、行距、字距、多语言适配、层级与阅读节奏 |
| 构 | 网格、对齐、间距、密度、视觉焦点与内容组织 |
| 质 | 图片、材质、阴影、层次与细节完成度是否服务内容 |
| 动 | 动效是否支持理解、反馈、节奏和注意力，是否造成干扰 |

结合品牌意图、受众、文化适配和用户理解，不以某种审美模板作为唯一标准。克制、无阴影或无装饰不等于完成度低；不要求所有界面使用动效。

分别记录产品界面质量和作品集展示质量，避免用后者替代前者。单一视觉分数根据项目设计证据与表达共同判断，在内部记录两者影响，不机械平均。此维度未规定二者固定比例，须用样本校准。

1 分：可观察到明显的层级、可读性、一致性或语境适配问题，影响理解/使用。
3 分：基本清晰、统一且适用，关键任务可理解，精细度或节奏尚有不足。
5 分：视觉语言有意图、细节精确、贴合产品与受众，并支持用户理解与行为。

无法读取页面图像时不评分视觉。静态材料的“动”单独标未评估，可依据其他可见子项评整体视觉，不按 0 处理。

### 5. 结果验证与目标闭环

验证应回应原目标。检查基线、对象、时间范围、方法、样本边界和替代解释。上线后增长不等于设计造成增长，合作反馈不自动证明转化提升。

未上线或保密项目可使用适当的可用性研究、任务完成结果、定性反馈或说明方法的匿名证据。无业务数据不自动判失败。未达目标但有合理诊断与迭代，也可体现高质量判断。

1 分：可读材料仅有无依据的成功宣称，或验证与目标明显不对应。
3 分：存在对应目标的验证，能说明结果，但方法或归因边界不充分。
5 分：目标与结果可追溯，验证方法合理、边界明确，能根据结果调整方案。

### 6. 个人贡献与设计价值

区分项目背景、团队成果与作者行为，寻找：发现了什么、判断了什么、推动了什么、改变了什么。职责列表不等于决策证据；“我主导”也不是证明。

判断作品是否体现设计的必要性、作者对路径/质量/风险/成果的具体作用，以及超出常规执行的贡献。影响力与协作采用所选层级和 IC/管理路径，L1/L2 不被要求带团队。

1 分：作品主要记录项目经历，难以确定作者承担的设计判断和作用。
3 分：职责与关键行动可区分，存在具体贡献，但决策或影响证据有限。
5 分：关键判断、推动与影响清晰可追溯，并解释与团队及其他因素的边界。

证据不足写“尚未充分证明”，不能据此断言作者没有能力或没有贡献。

## 统一计分

- 使用整数 1–5，2/4 对应相邻锚点的中间状态，不制造过度精确的小数评级。
- 先对照 `competency-models.md` 中对应场景和层级的基本要求，再用上述锚点评价证据质量。
- 通用总分为各项 `权重 × 评分 / 5` 之和，满分 100。全部 3 分对应 60 分，未定义“60 分必录用”等阈值。
- 同一问题指定一个主要计分维度；其他项可以解释影响，但不能把同一证据缺口变成多次惩罚。
- 未展示：素材可读，但必要内容未交代，可据此评价呈现不足。无法读取：缺少判断条件，标未评估。不适用：先适配该场景的等价证据，仍无法评价一级维度时不输出完整总分。
- 总分存在缺项则暂缺，不归零或重分配权重。图表用原始分值，完整总分仅在六维均可评时给出。
- 同时保存规则版本、确认的参照和读取范围；复评保持这些条件，变化时说明不可直接对比。
